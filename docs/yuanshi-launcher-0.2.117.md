# 圆石启动器 0.2.117 alpha：ys 原生键位与输入模式分开恢复

## 已确认与仍不确定的部分

2026-11-08 读取用户 0.2.116 实机安全日志：会话 t=3s 开始，终端类型仍为 10；
t=5s 已选择 RTC 手柄路径，t=40s 在游戏入口重新发送设备列表与来源。
用户仍看到 E/Z/Q 键鼠提示，说明 0.2.116 的路由修复不足以解决问题。
本轮没有主动进入实机或模拟器游戏。

对 SDK 专用加密配置进行内存分析后，确认其格式为 URI 百分号编码的 JSON，
其中 `GENERAL_DATA` 又是 JSON 字符串。实际配置包含两条
`_overrideControllerMapKeyList` / `_overrideControllerMapValueList` 原生键位记录，
且 `enableInputHotSwap` 为 false。没有读取登录密钥或登录库，没有输出配置内容或账号标识。
SDK 配置分析用的四个临时加密文件已清理，Switch 原文件未修改。

因此，“没有保存任何原生键位”不是准确结论；但存在键位记录，也不证明远端游戏成功应用它。
“启动后仍是键鼠模式”与“自定义键位是否恢复”需要分别验证，不能拿本地发送成功代替游戏响应。

## 本版改动

- 仅在 ys 的已恢复配置具有有效、数量匹配的原生键位表，且存在布尔型
  `enableInputHotSwap=false` 时，在 SDK 读取回包中请求把该选项设为 true。
  使用游戏自身的输入自动切换，而不是把手柄转换成键盘、修改按键或恢复本地改键。
- 按键表字符串、控制器标识、灵敏度和未知设置保持不变；不直接重写 SD 上的原始加密配置。
  游戏后续自己的 `cloud_set_data` 写入仍按正常存储流程保存。
- 未识别、旧格式、缺少选项或没有有效键位的配置原样回传，不猜测或新增游戏字段。
  zmd、bt 以及没有启用该策略的 SDK 使用方不改变行为。
- 增加固定的原生键位表数量、自动切换请求／原已开启／未改动诊断，不输出按键表内容。
- ACK 解码兼容官方 protobuf 中的可选 `seqId` 与扩展字段。
  前版要求 ACK 恰好只有 `msgId`，可能漏记接收确认；不能再用“没记到 ACK”直接判断包没到。

## 原生键位保存过程

1. 用户在游戏内修改原生手柄键位。
2. 游戏通过 SDK `cloud_set_data` 提交游戏设置；启动器在 SD 卡专用目录加密、原子保存。
3. 下次会话启动前恢复缓存；游戏通过 `cloud_get_data` 读取时，回传原生键位数据。
4. 本版对匹配配置额外请求开启游戏自身的自动切换，让真实手柄输入有机会激活手柄模式。

第 4 步的字段已在用户配置中观察到，但实际云端游戏是否采用、是否消除 E/Z/Q、
原生自定义按键是否按预期工作仍未实机验证。这里是有依据的候选修复，不是“永久保存已验收”。

原生键位字段也可对照开源 [Collapse GeneralData 定义](https://github.com/CollapseLauncher/Collapse/blob/main/CollapseLauncher/Classes/GameManagement/GameSettings/Genshin/RegistryClass/GeneralData.cs)。
该来源不证明云端的自动切换效果。
