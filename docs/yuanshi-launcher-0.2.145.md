# 0.2.145 手柄键位表格式修复

日期：2026-11-15（Asia/Singapore）。优先处理 ys 标准手柄输入，不改触摸入口、
终端身份、Xbox VID/PID、媒体、画质或其他游戏协议，不恢复本地战斗改键预设。

## 已确定的缺陷与复现

0.2.144 在 yuzu 进入了真实场景（`report-0144-pad-bindings-nov15`）：结束时解码
3,916 帧、0 解码错误，自动手柄探针到阶段 8。画面与用户截图相同，方向键切人和
底部部分操作显示问号；两个 Plus 探针未出现菜单。发送成功与手柄图标不证明实际响应。

本机游戏配置有三张 Rewired JoystickMap，XML 声明/属性分隔处的空格成了 `+`，例如
`<?xml+version=...?><JoystickMap+dataVersion=...>`。外层 URI 又把这些加号编码为
`%2B`。旧代码只检查是否含有类似 XML 的尖括号，没有校验 XML 能否读取。
这三张原始表均无法按标准 XML 解析，是确定的配置缺陷，但还不能当作全部输入问题的根因。

独立的 Off 对照运行 354 秒，没有游戏进入信号，不能用于判断“取消恢复后手柄就好”。
本轮不通过删除配置或伪造模式确认绕过问题。

## 修复边界

- 新增小型 `genshin_native_map` 模块，复用项目已有 TinyXML2，无 vendored 修改。
- 只对已识别的旧损坏 JoystickMap 格式恢复标签结构中的分隔空格，并校正已知
  `XInput+Gamepad` 标签及标准 Rewired schemaLocation 分隔符。必须通过 XML 解析并确认为 JoystickMap 才能回传。
- 不改动作 ID、按钮/轴 ID、键位表键名、控制器 GUID、布局、类别及用户改键。
  不全局替换 XML 文本中的加号，不重复百分号解码，不重新生成整张 XML。
- 合法 XML 原样保留；其他未知序列化仍沿用既有兼容规则。确认损坏且不能修复的
  JoystickMap 不作为一套残缺键位回传，保留原 vault 并给出数值诊断。
- 默认 Keybinds 应用格式修复。独立 Exact 对照仍逐字返回原串；旧 Full 实验不变。
- 原始加密保存、备份恢复与原子写入不变。修复只发生在回包中，正常游戏写回后再保存。
- 新增 `GAME_SDK_NATIVE_REPAIRED_XML_MAPS` / `GAME_SDK_NATIVE_INVALID_XML_MAPS`，
  每会话一次，中文可读、安全监控保留，不记录 XML、账号或凭据。

本机原配置的离线验证为 3 张修复、0 张无效，修复后均可解析。

## 标准物理位置映射

| Switch 输入 | 云端标准 Xbox 报文 |
| --- | --- |
| B（下）/ A（右）/ Y（左）/ X（上） | A / B / X / Y |
| 方向键上/下/左/右 | D-pad 上/下/左/右 |
| L / R / ZL / ZR | LB / RB / LT / RT |
| ＋ / − / 左摇杆按下 / 右摇杆按下 | Start / Back / L3 / R3 |
| 左右摇杆 | 对应左右摇杆的 X/Y 轴 |

这只是标准报文对应关系，攻击、确认、切人等动作仍由游戏原生映射决定，不把物理位置
映射误称作游戏动作已生效。本轮新增 16 个按钮/扳机和四轴正反端点经过过滤/组合及
生产 Session 编码的独立 golden-mask 检查，另验证 SDK 加密回包中的修复、写回与再次恢复。

框架关于动作与 ControllerMap 的关系见 [Rewired 官方 Controller Maps 文档](https://guavaman.com/projects/rewired/docs/ControllerMaps.html)。
本项目不能改云端游戏的框架设置，也不把框架通用说明当成当前云会话的响应证明。

## 验证状态

实际构建、校验值及在线结果见 [本轮验证记录](yuanshi-launcher-0.2.145-build.md)。
全按键报文通过不能替代真实场景中的镜头、菜单、ABXY 确认/返回、切人及重启键位验收。

后续同版本对照已排除“只是自动点击坐标”的解释：用户在 yuzu 手动点击也已采集和
提交，但当前控制节点的 TLS 证书日期校验失败；不可变 .144 同样失败。实机 .144
日志则记录了 GCC 就绪及 t=43s 进入信号。三个本轮派发控制候选均独立检出证书过期。
这项测试环境阻碍与游戏内键位问题分开跟踪，不据此篡改实机可用输入协议或关闭 TLS 校验。
