# 0.2.144 回到移动端触摸＋Xbox 基线（离线候选）

日期：2026-11-15（Asia/Singapore）。本轮用户明确要求不进入游戏、不排队。

## 收敛范围

“第二条路线”指移动端终端身份 3、`android_mihoyo`、触摸进入标题页、Xbox 手柄操作。
0.2.133 与首次内部 0.2.138 有实际进入场景的记录，但不能据此声称游戏内手柄、
菜单、重启键位保留已经完整通过。本版恢复它们的**入口行为基线**，不是把整个源码
回滚到旧 NRO，也不是声称逐字恢复了首次内部产物。

- 在通道就绪时发送 Xbox 列表，并在真实通道/游戏进入交接时清除一次旧输入。
  移动端的 mask 12 表示释放触摸与手柄状态，不是模式激活或云端确认。
- 固定单指 `(0.5, 0.947)`，Down → 保持 120 ms → Up；取消 y 坐标轮换及自动 Move。
- 撤掉 touch-first / 延迟声明、自动触摸/A/B 轮换、键盘 Space 和移动端 A 兜底。
  ys 不再启用旧 `.click` 四次入口实验。旧测试文件保持原样，但不再切换这些路线。
- 仍保留普通用户最多 10 次、pad 自动测试最多 60 次的有限预算；真实 SDK 进入信号、
  用户接管和手动继续停止自动进入。游戏阶段的物理 A/B/摇杆输入不因此屏蔽。

## 本地修复

新增小型 `LauncherPointerTap` 状态策略，由实际串流 worker 使用：只有发送成功的 Down
才持有触点；Up 失败保留持有状态并等待 100 ms 重试，不能开始另一个手动/自动 Down。
SDK 进入或手动接管时尽快释放，后续失败仍按间隔重试；输入通道重建清除旧触点状态，
退出时尝试最后一次释放，不把本地接受当作云端回执。

0.2.143 B 探针被持续发送器覆盖为 A 的实验缺陷随轮换路线一并移除，不再继续该实验。
保留原生配置加密/原子保存、Keybinds 默认恢复、Exact 独立对照、Xbox 默认标识、
真实物理键值、ZL 体感、软硬解、媒体恢复及有限输入诊断；不恢复启动器本地改键。

新增固定安全事件 `AUTO_ENTRY_BASELINE_TOUCH_ONLY`，中文可读，并保留在安全日志与
监控证据里；历史事件解析仍保留以便阅读旧报告。没有新增账号数据或逐帧日志。

## 验证边界

本轮只运行离线 host 回归、源码路线检查及 devkitA64 构建，结果与产物校验见
[构建校验](yuanshi-launcher-0.2.144-build.md)。不启动 yuzu，不连接云端，不读取账号
凭据，不改动运行目录或加密游戏设置，不提交、推送或发布 Release。

离线通过不能证明云端接受触摸、游戏内手柄有效或重启保留已通过；下一次在线验收应
固定这条入口基线，逐项验证进场、相机/菜单及跨会话键位，不再混改输入路线。
