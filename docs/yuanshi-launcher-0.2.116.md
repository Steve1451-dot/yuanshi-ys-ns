# 圆石启动器 0.2.116 alpha：ys 原生手柄输入路由

## 最新实机反馈与日志

用户报告：第一次在游戏里设置手柄后，第二次进入显示电脑键鼠键位，手柄无法操作。
2026-11-08 只读取得的 0.2.115 安全日志中，两次会话为同一轮 t=96s 与 t=310s：

| 项目 | 第一次 | 第二次 |
| --- | --- | --- |
| 终端类型 | 10 | 10 |
| Xbox 身份 | 1118 / 654 | 1118 / 654 |
| 云端声明 Xbox / PS | 均为 0，本地强制 Xbox | 相同 |
| 独立 GCC 控制连接 | TLS 校验失败，回退 RTC | 成功并优先接管输入 |
| RTC SCTP / 数据通道 | 已就绪 | 已就绪 |
| 配置读回及大回包 | 117217 字节，已提交发送 | 218869 字节，已提交发送 |
| 实体按键 | 已采集 | 已采集 |

没有证据表明程序把终端从 Android 改为 PC：两次原本就是终端 10。
第二次实际出现键鼠界面仍是故障，不能用 Xbox 声明或本地发送成功来代替游戏响应。
日志尚未出现针对大配置回包的匹配 ACK，因此“已发送”也不能等同云端采用了键位。
输入路由差异是已确认的事实，但是否为游戏键鼠模式的唯一原因尚未实机证明。

## 本版修正

- 仅对 **ys + 标准 Xbox 身份 + 云端未开启手柄标志** 的强制原生手柄会话，
  优先使用已经就绪的 RTC 输入路径。RTC 未就绪／暂时失效时，仍可用现有 GCC 回退。
  不双通道同时发送按键，不跳过 TLS 校验，不更改终端、CPS 或手柄身份。
- 云端已正式开启的手柄、其他应用及 PS 身份保留原来的 GCC 优先策略。
- 给实际输入通道增加代次：即使 `input_ready` 一直为真，GCC ↔ RTC 切换也会触发
  重新发送设备列表、输入来源与中性帧，避免把旧通道的“已声明”状态带到新通道。
- ys SDK 报告进入游戏后，再声明一次手柄来源，补中性帧。入口鼠标点击和真实游戏输入
  分开处理；同一通道上仍保留尚未送出的入口 Up，避免丢失按键／触点释放。
- 当前已经使用 RTC 时，闲置 GCC 的断开不再向云端发送全局输入重置，以免误伤正在工作的手柄。
- 增加固定标签的通道选择／重新声明事件，不逐帧打印按键，也不记录配置值或账号凭据。

没有恢复本地按键映射，没有把云端游戏强行换成另一个平台，没有删除或篡改用户保存的游戏配置。

## 验证边界

离线测试覆盖恢复配置有／无、云端手柄标志有／无、ys／其他应用、GCC 与 RTC 都在线、
RTC 短暂掉线回退再恢复、通道代次、列表／来源／中性帧的真实编码，以及不双发按键。
构建与测试结果见随包构建记录。

本版未主动启动实机或模拟器游戏。修复了输入路由和声明生命周期的缺口；
不能据此宣称游戏原生键位已永久保存，或第二次进入的键鼠模式已经实机消失。
