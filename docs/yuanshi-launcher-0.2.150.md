# 圆石启动器 0.2.150 alpha 候选

2026-11-16（Asia/Singapore）。针对 149 弱网测试约 141 秒信令断开、直接结束串流并弹日志的情况。

## 自动恢复（ys 与共用 RTC 实现的 bt）

- 只恢复已经成功连接过的派发会话。复用内存中的原会话授权，后台连接已派发 WSS 地址，
  重新发送 StartGame 授权，不重新登录、不扫码、不排队，不保存或打印令牌。
- 信令重连在独立线程中进行；该线程独占 socket，原网络线程继续驱动已有媒体。
  保留最后画面与 SDK 可靠队列/游戏配置。恢复中显示轻量中文提示，不自动打开诊断页。
- 若媒体通道仍有效则优先保留；媒体失败、控制通道失效或重新授权后媒体未恢复时，
  在预算内重建 peer。恢复期允许服务端给出新的 ICE/DTLS offer，仍验证证书指纹。
- 只有重新授权、收到视频、解出新画面及控制通道恢复后才记录恢复成功。
  恢复时重新声明设备与 Xbox 手柄，清理旧按键状态，再恢复普通输入。
- 单次异常最多 3 次连接尝试、总预算 30 秒；短期反复断线共享预算，持续健康 30 秒后
  才获得新预算。每次连接超时设为 3.5 秒，带退避，可取消并回收线程。
- 恢复失败不发送 StopGameReq 来主动结束云端游戏；最终再提示手动重连。
  用户明确退出、服务器结束/登出、授权拒绝、协议错误和证书错误不无限重试。

这是同一派发会话的恢复尝试，不保证云服务端仍保留该分配。不能恢复已失效的授权、
不能跨网络条件保证成功，也不能保证恢复时不掉帧。新的退避逻辑尚需 Switch 弱网验收。
本版未更改导致 2.84 秒 peer 单次调用的库内部实现，不能声称该长耗时已根除。
zmd 使用独立协议，本版没有将该 RTC 恢复流程直接套到 zmd。

## 手动帧率（ys / zmd / bt）

删除共用策略中的自动降帧/升帧决策和两个串流视图中的自动 FPS 发送分支。
网络损伤、解码队列拥塞或码率达到下限均不再把 60 FPS 自动改成 30 FPS。
保留手动 30/60 选择与持久化、码率上下限与有界码率保护。UI 不再显示“自动调整 30 帧”。
这保证客户端不会擅自改变请求；不能保证弱网下实际收到/显示的帧率始终达到请求值。

无新本地改键、无 PS5 身份、无 PC 路线。旧 NRO、登录库和配置不删除。
