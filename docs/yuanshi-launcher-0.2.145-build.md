## 测试入口边界

标题必须通过触摸进入；不再把标题不响应手柄作为游戏内手柄故障证据。
新增三重 opt-in 的开发者手动按键探针，默认用户不启用：正常 autotest、pad
autotest 和精确的 `CGNX_PAD_MANUAL_V1` 标记必须同时存在。

探针只接受 1–32 的递增请求编号和单个标准按钮/轴，保持 400 ms 后松开，
最少间隔 1400 ms。SDK 进入信号之前不读取/执行按键；网络线程另有独立到期松开，
避免 UI 卡住后持续按压。真正使用探针前仍需确认画面已经进入场景。
本轮没有发出任何手动按键请求文件。

仅该专用诊断模式使用视频中心触摸；普通入口仍用既有固定坐标，不恢复坐标轮换、
键盘、延迟声明或标题手柄兜底。普通物理触摸不变。

## 实机与 yuzu 的已确认差异

从用户提供的 MTP 路径只读复制了三份日志和九份限额历史日志，未读取登录凭据、
复制账号文件、修改 SD 卡或部署程序。

| 同版本 .144 | 独立 GCC 控制连接 | 游戏进入 |
| --- | --- | --- |
| 实机日志 `stream-safe-08.log` | HTTP 101，`CONTROL_WSS_READY`，选择 WSS 输入 | t=43s `GAME_SDK_WILL_ENTER_GAME` |
| 当前 yuzu 不可变 .144 对照 | HTTP 0、curl 35，TLS 失败后回退 RTC | t=422s 仍未进入，主动结束测试 |

yuzu 两轮版本的物理鼠标点击均已采集并交给发送接口。SCTP 日志可见底层 SACK，
但没有观察到应用输入/控制心跳回包；底层确认不能当作云端游戏响应。
.145 与不可变 .144 均遇到控制连接失败，不能把本次卡标题仅归因于新增 XML 修复。

进一步只读核验：yuzu Windows Schannel 报“收到的证书已过期”。对本轮派发
提供的三个控制候选地址分别执行无会话、无 HTTP 的 TLS 检查，均得到
`RemoteCertificateChainErrors / NotTimeValid`；叶证书有效期止于
2026-03-16 23:59:59 UTC（2026-03-17 07:59:59 新加坡时间）。主机 OpenSSL
也返回 curl 60 / verify 10。TCP 本身可连通。

新增 `scripts/test-cloudgenshin-control-tls.ps1` 可重做此检查：从已有 trace 提取
已派发、无 query 的控制地址，仅输出证书日期和校验分类，不输出地址/凭据，
不发账号或会话请求。证书校验回调只接受 `SslPolicyErrors.None`。

这确认了当前电脑测试控制连接的阻碍，并不证明全部云节点都使用相同证书，也不能
仅凭这些日志确定实机为何握手通过（节点或 TLS 校验环境仍可能不同）。不关闭证书
校验、不修改电脑日期、不把 TLS 失败误报为“触摸没点到”或“游戏已可操作”。
