# 圆石启动器 0.2.148 alpha 候选

2026-11-16（Asia/Singapore）。目标是减少本地接收长停顿，不通过降低画质来隐藏问题。
这是待实机对照的性能候选，不是“所有网络均不卡”的保证。

## 已修改

- 收包、音频、视频解码分别请求线程优先级 `0x32 / 0x33 / 0x34`，
  日志后台线程请求 `0x3c`。仅在进程允许的优先级范围内设置；失败保留原调度，
  记录实际优先级及系统错误码。保留原核心掩码、等待/退避，不绑核、不超频。
- 安全日志仅在复制有界记录时持有事件锁；排序、去重、预算和字符串整理移到锁外，
  去除逐条遍历整个列表的重复检查。归档按序号合并保留事件，避免乱序和重复。
  原有安全日志自动保存、16 段轮转、账号保护不变。
- 可选 `audio.log` 从收包回调和音频队列锁内的直接 SD 写入，改为后台合批写入。
  每 250 毫秒合并，待写最多 128 条 / 64 KiB，每条最多 2 KiB，单次会话最多 512 KiB。
  写盘慢时只丢调试文本，不阻塞等待写盘、不增加媒体缓冲；关闭串流诊断时不启动该写入线程。
  正常安全事件日志不受此 512 KiB 调试文件上限影响。
- 新增单次收包调用最大耗时、超过 16.667 毫秒的调用次数；ys/bt 另拆出 SDK 维护和
  独立控制通道维护耗时。ys / zmd 均记录现有 RTC RTT、实际线程优先级，以及音频日志
  后台写入耗时/丢弃/失败计数。只在原有快照周期输出数字，有中文说明。

## 沿用，不改

NVDEC/软件回退、解码队列上限、RTP 修复与关键帧重同步、音频格式/播放缓冲、
画质与帧率设置、登录库、原生 Xbox 输入与游戏内键位保存均保持原逻辑。
ZL 体感即时响应，轴方向、灵敏度和 LB 优先不变，没有重新加入 100 毫秒等待。
没有复制手机 APK、关闭鉴权或 TLS 校验，也没有把缺失参考帧的压缩数据硬送解码器。

## 下次日志能区分什么

| 计数 | 含义 |
| --- | --- |
| `RTC_PEER_CALL_MAX_US` | 单次 libpeer 轮询的墙钟耗时，包含系统抢占，不能单独证明是网络或驱动阻塞 |
| `RTC_PEER_SLOW_CALLS` | 超过一帧预算的调用数，不是丢包数 |
| `RTC_SDK_POLL_MAX_US` / `RTC_CONTROL_POLL_MAX_US` | SDK 维护与独立控制通道各自耗时，仅 ys/bt |
| `RTC_NETWORK_RTT_MS` | 现有连接估计的往返延迟，`-1` 表示未知，不额外发送探测 |
| `*_WORKER_PRIORITY` / `*_WORKER_PRIORITY_ERROR` | 实际优先级 / 系统设置错误码；主机测试为 `-1 / 0`，不改变主机调度 |
| `AUDIO_DIAGNOSTIC_WRITE_MAX_US` | 后台调试写入耗时，不是收包线程等待时间 |
| `AUDIO_DIAGNOSTIC_DROPS` | 调试文本达到队列或会话上限而丢弃，不能当作音频丢包 |

上一轮实机出现过接收循环约 0.68 秒长停顿，伴随等待关键帧；硬解平均约 3.5 毫秒。
这些只能确定卡顿表现与本地长停顿同时存在，不能据此把所有原因归咎热点，也不能证明
本次调度调整已消除问题。收包函数内部、系统调度、SDK 文件访问与链路抖动仍需对照新计数。

本轮不启动 yuzu、不消耗在线排队时间；构建与主机回归范围见
[构建校验](yuanshi-launcher-0.2.148-build.md)。安装仅新增/替换程序，不删除旧 NRO 或配置。

调度接口依据 [libnx thread.h](https://switchbrew.github.io/libnx/thread_8h.html)
及 [SVC 接口](https://switchbrew.github.io/libnx/svc_8h.html)；默认 newlib 线程实现见
[libnx newlib.c](https://github.com/switchbrew/libnx/blob/master/nx/source/runtime/newlib.c)。
默认工作线程并非都被固定在一个核心上，本版不作这一假设。
