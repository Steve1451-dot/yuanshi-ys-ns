# 圆石启动器 0.2.115 alpha：修复大配置回传

## 本次证据

2026-11-08 读取连接的 Switch 安全日志与 SDK 专用配置文件，未读取登录凭据，未启动游戏。
最后日志仍为 0.2.113，同一轮两次串流中出现：

- t=35s 配置写盘成功；t=108s 下一次串流从 SD 恢复 1 个配置键。
- t=119s 游戏请求读取命中；t=131s 再次写盘成功。
- 离线验证配置快照的认证与账号隔离，恢复到 1 个 87834 字节的不透明字符串。
  只记录大小和结构计数，不输出账号、键名、配置值或密钥；不能从这份不透明内容证明其中包含手柄绑定。
- 按生产回包结构计算：JSON 明文 87898 字节，加密 Base64 正文 117208 字节，
  尚未计入 protobuf 封装就已经超过 64 KiB，且未超过原 256 KiB 明文限制。

因此，“写盘／读回成功”并没有证明配置已回到云端。

## 确定的代码缺陷

SDK 桥整包回传恢复的配置，AES 填充与 Base64 会继续增大消息。
原 `control::EncodePacket` 对所有命令统一限制 64 KiB；大配置因此返回空字节数组。
`Session::send_sdk_proxy` 又把这个空数组装进有效的 signaling proxy 头，
可能报告发送成功，实际却没有 SDK 配置正文。

原主机测试仅用很短的合成字符串，发送回调也未经过生产控制包编码，未覆盖这个边界。
本次先新增贯穿实际编码器的 87834 字节用例，旧实现确实失败，再修复。
临时游戏配置分析副本已清理，Switch 原文件未删除、改写或重置。

## 修复方式

- 遵照本地留存的官方 `cg-sdk.c4be3733.js`：`RmqSender.send` 使用
  `seqId=seqCnt=1` 的完整消息，Packet 正文长度为 32 位。不另行发明分片协议。
- 仅命令 1900 的控制包编码／解码上限调整为 512 KiB；其他控制命令仍为 64 KiB。
- SDK RMQ 接收使用独立的 512 KiB 加密线上限；JSON 明文仍限 256 KiB／64 层，
  SD 配置仍受原来的容量、账号隔离和认证校验约束。不是取消长度限制。
- 控制包编码失败立即返回失败，禁止继续发送空 proxy 并误报成功。
- 增加一次性大回包发送／失败／匹配 ACK 事件。ACK 必须匹配内层发送消息号，
  不是任意 ACK；只证明服务器队列接收，不证明游戏应用了键位。

不修改按钮位置、不恢复本地改键功能，不改登录、视频解码、画质或音频策略。
原 SD 上的游戏配置与登录文件不需要删除或重置。

## 验证边界

新增合成用例贯穿实际 SD 存储、SDK 加解密、控制包、信令编码和会话 WebSocket 发送。
覆盖 87834／200000 字节（含引号、反斜线、换行与 NUL）、入站大消息、ACK 匹配、
发送失败及命令专属长度边界。结果见随包构建记录。

按用户要求没有运行本版实机游戏测试。可以确认修复了可复现的大配置传输阻断；
还不能保证游戏原生手柄绑定已经永久保存，仍须观察游戏实际是否采用该配置。
