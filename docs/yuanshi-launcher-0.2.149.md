# 圆石启动器 0.2.149 alpha 候选：固定 ys 原生手柄方案

2026-11-16（Asia/Singapore）。用户要求固定此前能用的原生键位，不再让配置随回写漂移。

## 行为

- 保持终端类型 3、固定触屏标题入口、原生 Xbox 报文、当前手柄身份/按钮编码不变。
  不退回 PC/键鼠，不重新加入启动器本地战斗改键或 PS5 路线；ZL 体感不增加等待。
- 仅 ys 的默认 Keybinds 恢复模式启用固定保护；zmd/bt、Off/Exact/Full 比较模式不变。
- 从本地游戏配置中选取已由游戏保存为手柄的方案：必须同时有可解析的手柄映射、
  非默认用户项中的 `isUsingJoypad=true`、`checkedDefaultUsingJoypad=true` 和非空 `joypadGUID`。
  单有三条键位表、报文发送成功、或触屏默认值都不能当作可用模板。
- 一旦选定，后续 SDK 回写不再替换固定的手柄映射、已保存的两个输入开关，及上述三项
  手柄选择字段。SDK 当前缓存和加密存储使用同一受保护结果，重进后不会又读到原始触屏回写。
- **只固定输入字段**。最新的其他设置、用户本地数据与未知新字段继续更新；不将整个
  `USD_*` 文件或整份游戏配置冻结。没有增加账号凭据文件或公开的用户专属按键模板。
- 固定后，再在游戏里改键不会自动变成下一次默认方案。这是本次要求的固定行为；
  不是声称游戏内改键功能被自动持久化。

## 原设置已经被覆盖时

启动前可检查当前账号/渠道的加密交替槽及备份，只有通过同一 AAD 验证、匹配现有账号
游戏键、且含明确手柄选择的历史配置才会用于恢复输入字段。较新的正常手柄配置优先。
新会话启动快照增加作用域绑定；旧的无绑定明文快照不自动导入，以免跨账号/渠道套用。

若没有任何满足条件的配置，日志会显示“尚无已确认的手柄存档，不会把触屏状态固定为默认”。
此时等待游戏第一次明确保存手柄配置再固定，不编造 GUID，也不把坏状态永久锁住。
恢复期间不会删除或覆盖旧 NRO、登录文件、加密游戏数据密钥。

## 诊断与限制

`GAME_SDK_NATIVE_CONTROLLER_LOCK_READY` 是本地固定方案就绪，不是云端采用确认；
`BASELINE_RECOVERED` 表示从受校验备份找到了候选；`LOCK_PROTECTED` 表示本地保护已运行。
游戏回写对比仍报告**保护前的原始回写**，不把客户端自己的补丁当成成功回执。
另记录本地保存、实际 SDK 回包、游戏原始回写各自包含多少手柄模式用户项。
保护本地配置不等于阻止云端游戏在当前运行中自行切回触屏；若仍发生，需根据这三个阶段
继续确认采用环节，不能把本地就绪日志当作实机手柄验收。

用户这次提供的新运行日志仍标记 0.2.147，用户已确认尚未更新 148，因此不能拿它比较
148 优化后的流畅度。本轮优先固定手柄配置，不新增性能参数或在线排队实验。
旧日志的 `MAPS_MATCH_REPLY=0` 只是配置往返线索，不能单凭它证明手柄无效的唯一原因。
