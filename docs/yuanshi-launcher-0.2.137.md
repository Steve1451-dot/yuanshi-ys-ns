# 0.2.137：标题页输入互扰修复候选

日期：2026-11-12。基于当前 0.2.136 工作区累计修改，保留其原生键位、Android
终端、Xbox One 身份与媒体链路。不恢复 0.2.117 的完整配置强制回传。

## 已确认的代码问题

- 官方 APK `GamepadManager.sendGamepadState` 在 `isChanged()` 时才发状态。
  当前客户端即使完全空闲，也约每 16 ms 发一次中性手柄帧；触摸 Down 与 Up 之间
  仍插入多份该帧。这是确定的行为差异，但它是否能解释所有标题页失败尚未证明。
- type-31 是 `RESET_GAME_INPUT_CONTROL`，清除指定设备的按住状态；不是切换输入模式的命令。
  0.2.136 的四秒重发实验没有成功进入的报告，不能继续当作模式激活方案。
- 手动继续和默认自动进入各自使用 finger 0，之前可在旧自动按压尚未释放时开始手动点击。

## 修正

1. 仅对 **ys + 终端 3 的标题页阶段** 去除已经成功提交的重复空闲手柄帧。
   真实活动／长按仍按原节奏发送；活动后的释放、失败重试、通道切换、设备重新声明、
   输入重置、UI 捕获要求的强制中性帧均保留。游戏进入信号到达后恢复原发送节奏，
   包括弱网下重复中性帧；其他游戏与终端的发送行为不变。
2. 去掉四秒周期 reset。旧 `.redeclare` 测试标记只产生“已忽略”事件，不删除用户文件。
   真实通道重建与游戏入口交接时的一次性状态清理仍保留。
3. 手动继续优先：停止自动序列，等待其旧按压成功释放，再开始手动 Down。
4. 新增固定安全诊断，区分去重启用、旧周期 reset 标记被忽略、手动继续接管。
5. 仅在 ys 显式 `.pad` 测试标记开启时，两个完整触摸尝试之后，穿插一次使用当前
   正确 Xbox 身份的 A 确认比较。仍由原有总次数上限与 SDK 进入信号约束；普通用户
   不启用该比较，所有 Down 必须先释放才能尝试下一个输入路径。

不改原生键位数据、不改登录库、不修改触摸坐标、媒体安全策略或解码路径。

## 验证边界

主机测试能验证真实 Session 的编码与发送次数，不能证明 pod 对触摸作出了响应。
需另看 yuzu 真实云会话是否出现游戏进入信号与画面，Switch 持久化与手感仍需实机验收。
完整结果及产物校验见构建记录；不能把“发送成功”或“无解码错误”写成“标题页已修好”。
